# Decisões de arquitetura (ADRs)

> Última atualização: 24 de setembro de 2026

Cada ADR registra uma decisão: o contexto, as opções consideradas, a escolha e
as consequências. O [ROADMAP](../ROADMAP.md) diz **o que** será feito; os ADRs
dizem **por quê**.

Um ADR não é reescrito quando a decisão muda — um novo ADR o substitui, e o
antigo passa a status **Substituída**, apontando para o novo.

| # | Decisão | Status |
|---|---|---|
| [0001](0001-execucao-descentralizada-e-ecossistema.md) | Execução descentralizada, ecossistema de dados compartilhado no Supabase | Aceita |
| [0002](0002-sentry-nao-se-aplica.md) | Sentry não se aplica à skill; observabilidade local | Aceita |
| [0003](0003-painel-localhost-como-app-local.md) | Painel localhost como app local novo, não extensão do gerador | Proposta |
| [0004](0004-identidade-de-bot-supabase-auth.md) | Identidade de bot via Supabase Auth, com RLS por bot | Proposta |
| [0005](0005-rebrand-intuscripto.md) | Rebrand Aspira → IntusCripto, com superfícies preservadas | Aceita |

**Proposta** significa que a direção está registrada, mas a decisão é
confirmada no início da fase do ROADMAP que a executa.
